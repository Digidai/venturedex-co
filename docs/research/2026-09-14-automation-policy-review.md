## 调整清单

| 原规则/问题 | 判断 | 实施后的规则 |
| --- | --- | --- |
| 一个任务只能一个周期 | 防重复有必要，不能否定人工清理范围 | 一个活动租约、有限任务快照、多批不可变 manifest；中断恢复未完阶段 |
| 每批必须 10–20 家 | 导致少量真实候选无法处理、补无关候选 | 无硬性最小/最大数；10–20 仅为规划参考；有搜索证据的空结果合法 |
| 最多发布 5 家 | 无质量/容量实证，制造合格积压 | 所选项目逐项过全部门禁；按真实预算/依赖收尾，不以第五家为停点 |
| 每次只复审 3 家、planner 上限 5 | 掩盖积压、拖延已具备资料的项目 | planner 默认显示 10，可任意正数或 `--all`；保留优先级、到期及人工触发 |
| 至少搜索三类来源，即使仅清积压 | 覆盖建议被误用为每次必做工作 | 新发现倡导互补来源并记录真实尝试；复审池无需重新发现；单项原始证据不放松 |
| 复审历史最多 30 次 | 达上限不能继续且易诱发删历史 | 保留全部有序实际记录；无新证据不盲重试 |
| 必须不同名字复核截图 | 独立性有价值，但字符串比较不能认证独立人员；曾阻塞单操作者任务 | 优先独立复核；允许显式同人 `second-pass`，六项实际验收/最终哈希/展示检查不变，承认独立性降低 |
| 发布凭据故障就不能研究 | 依赖与阶段错配 | 显式 research-only 预检，无凭据/npm/Actions也可完成范围内研究；不能替代发布门禁 |
| 任意旧 SHA 的 CI 取消即整项失败 | 与最新优先的 CI 并发策略冲突 | 仍要求精确实际 release SHA 成功；后继覆盖须证明祖先关系及任务路径不变，并另查 CI/Deploy/live |
| GSC 自动队列大于 10 即报错 | “retry pending”遇到大积压无法使用 | 自动选择器透明分页，展示总数/余量；明确 URL 不静默遗漏；点击前后事务保护不变 |
| GSC/延迟邮件未完成就否认发布 | 混淆网站、请求收录和外部交付 | 分别记录 publication/indexing/newsletter；网站已验证可完成并保留索引跟进；明确索引专项目标仍未完成 |
| 网络探测错误=内容发布错误 | 证据不支持该推断 | 记录探测警告；需其他成功 live 证据；真实断言失败或完全无成功验证仍阻塞 |
| 每次追加日志再提交部署日志 | 产生重复全量验证/部署，还会取消前一 CI | 每次写外部 receipt/memory；仓库只追加重要教训/纠错；最终 CI 回执外置 |
| reward 为修好的测试错误、正常重试扣分 | 混淆质量与成本，惩罚提前发现问题 | 停用加减总分，记录质量、进度、外部状态和实测成本；不改旧分数 |
| 七个清单结果直接相加 | 重复统计同一公司，误报积压 | 新增只读 `curation.py summary`，按唯一 slug 与当前有效 overlay 汇总 |
| Weekly 验证后盲目 restore seed | 与现有临时 seed 机制矛盾，可能覆盖其他改动 | 非预期 tracked 变化先调查，保留所有权，不做惯性恢复 |

实际资源预算应来自用户/平台限制及本次可用资源；门禁/部署预留使用近期实测。没有证据支持统一 45 分钟或更大的新数字，因此没有用新的任意硬上限替换旧的 5。

## 保留的合理边界

- 原始融资来源、日期、独立公司、逐项研究与产品证据、品味判断、官方品牌、截图落盘和六项检查。批量效率不等于免审；证据不足不能凑数。
- fresh 的 30 天发现窗口保留；旧队列可以凭新证据、到期或人工触发复审，不强制伪装成新融资。投资机构 90 天新鲜度用于减少无变化重查，实质变化仍要更新。
- 单写者租约、CAS、精确 worktree 所有权、非强制 Git、遥远端数据删除保护、串行部署、精确实际 release SHA 与 live 验证。
- GSC 的精确 URL、begin-before-click、至多一次点击、未知结果不重试；10 条是可分页操作单大小，不声称是 Google 配额。实际配额/登录保护照旧。
- Newsletter 既有 Daily 6 小时/Weekly 24 小时延迟、幂等发送和退订保护不变；本任务不手动触发邮件。
- Weekly 默认一期及 5–7 个主题 picks 是不同的编辑产品约定，不套用 Daily 的工作量结论而随意改动。Launches/importer 的数据删除、抓取和批次保护也不在此次更改范围。
